# Kenのデンモク(REALITY 歌配信用)

REALITYの歌配信で使う、曲リスト・練習中ランキング・リクエスト受付のWebページです。

## 画面

**リスナー画面**
- 歌える曲リストの検索(ひらがな/カタカナ・全角/半角の違いを吸収)
- 練習中楽曲のランキング(リクエスト数順)
- 楽曲リクエスト(練習中の曲から選ぶ/新しい曲を入力)

**管理画面**(編集権限がある人だけに表示)
- 歌える曲の確認・追加・編集・削除
- 練習中楽曲の確認(リクエスト数つき)、歌える曲への移動
- リクエストの確認(未対応/対応済み)、未登録曲を練習中に追加
- 配信者名の設定、CSVでの一括登録

## データ

| コレクション | 項目 |
|---|---|
| `songs` | `title`(楽曲名), `artist`(アーティスト名), `jasrac`(JASRACコード), `nextone`(NexToneコード), `status`(`ready`=歌える / `practice`=練習中), `createdAt` |
| `requests` | `title`, `artist`, `songId`, `nickname`, `message`, `status`(`new` / `done`), `by`, `createdAt` |
| `settings/main` | `name`(配信者名) |

CSV一括登録の列順: `楽曲名,アーティスト名,JASRACコード,NexToneコード,区分,発売年`(区分は「歌える」か「練習中」、発売年は任意)

`data/songs_1980-2025.csv` は1980〜2025年の日本の楽曲10,000曲のリストです。Wikidata(CC0)から取得し、Wikipedia記事の多い曲を優先して選んでいます(JASRAC・NexToneコードは空欄)。

## 動作環境について

現在の `index.html` は claude.ai の Artifact 上で動く版です。データの保存には claude.ai のデータベース機能(`window.claude.use("db")`)を使っているため、
GitHub Pages などで単体で開いた場合は画面は表示されますが、曲データの読み書きはできません。
一般のリスナーが使える形で公開するには、Firebase / Supabase などのデータベースにつなぎ替える必要があります。

## 曲カタログ(catalog.json)

`catalog.json` は1960〜2025年の世界の楽曲 約58,800曲の検索用カタログです。形式は `[曲名, アーティスト, 発売年]` の配列で、人気順(Wikipedia記事の言語数順)に並んでいます。
出典は Wikidata(CC0)。曲名・アーティスト名は日本語表記を優先し、なければ英語表記です。
リスナーはリクエスト画面や曲検索からカタログの曲を選んでリクエストでき、管理画面では「曲カタログから追加する」で歌える曲・練習中に登録できます。
JASRAC・NexToneコードは公開データが存在しないため含まれていません。


## 日本楽曲10,000曲の検索対応（2026-11-05）

- `data/japanese_popular_10000.json` は、既存の `data/songs_1980-2025.csv` に収録された10,000曲を検索用に整形したものです。ファイル名とは異なり、収録範囲は **1980〜2026年** です。
- 検索用項目は **曲名、アーティスト名、発売年** です。Wikipedia記事のカバレッジを参考とした既存の選定データであり、日本の公式売上チャート上位10,000曲という意味ではありません。
- 出典データは、既存のREADMEに記載された **Wikidata（CC0）** です。JASRAC/NexTone作品コード、カラオケ配信可否は未確認のため付与していません。
- `data/japanese-catalog-loader.js` が既存の世界カタログ（`catalog.json`）と日本楽曲を結合します。曲名＋アーティスト名を正規化して重複表示を抑えます。日本楽曲を検索結果の優先順に配置します。
- このカタログは**楽曲検索候補**であり、配信者が「歌える曲」に登録したことを意味しません。既存の管理リストやリクエストの記録は変更しません。
- データセットの10,000曲は重複なしで検証済みですが、世界カタログと重複している曲もあるため、検索全体のユニーク増分は10,000曲より少ない可能性があります。


## 追加10万曲データ生成パイプライン（VocaDB）

`scripts/build_vocadb_100k.py` と `.github/workflows/build-vocadb-catalog.yml` を追加しています。
実行成功時、実在する楽曲メタデータのうち既存の検索用データと重複しない曲名・アーティストの組み合わせを10万件選別し、`data/vocadb_100k/part_001.json` など20分割ファイルと `manifest.json` を公開します。
公開ページは `manifest.json` を読み取り、**生成と検証が完了した場合だけ**追加カタログを検索に統合します。生成失敗時は従来の検索データを維持します。

出典は [VocaDB](https://vocadb.net/) の公開メタデータを収集した [amiadesu/VocaDBSongs](https://huggingface.co/datasets/amiadesu/VocaDBSongs) です。VocaDBのデータベースコンテンツの利用条件（CC BY）に従い、出典表示を維持します。この10万曲はボーカロイド・UTAU関連曲が中心の**検索候補**であり、J-POP全般の人気上位曲を意味しません。出典情報、リリース年の欠損数、重複除去後の候補数は、生成時の `manifest.json` に記録します。JASRAC・NexTone作品コード、カラオケ配信状況は未検証です。
